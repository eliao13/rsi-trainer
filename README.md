# RSI Trainer

Practise reading RSI Trader's setups: see the chart up to his entry, call the side and size, then replay the trade minute by minute against his alerts.

Live: https://eliao13.github.io/rsi-trainer/

## Develop

```bash
npm install
npm run dev      # local dev server
npm test         # unit tests (indicators, exits, message filter)
npm run build    # production build into dist/
```

Pushing to `main` runs the tests, builds, and publishes to GitHub Pages (`.github/workflows/deploy.yml`). Pages must be set to **Settings → Pages → Source: GitHub Actions**.

## Layout

- `src/App.tsx`: one round (guess → replay → done), saved progress, keyboard shortcuts
- `src/components/`: chart (canvas), action bar, timeline, results, history, charts dialog
- `src/lib/`: indicators (RSI, bands, TRAMA, VWAP), trade maths (auto-sell, rule-based exit, lessons), mistakes pile, message filter, storage, chart images
- `public/data/`: generated by `build_data.py`
  - `trades_index.js`: the trade list (~1.2 MB), loaded first
  - `detail/YYYY-MM.js`: each month's option-price paths and RSI Trader's messages, loaded per trade
  - `bars/<instrument>_YYYY-MM.js`: 5-minute bars by month; `m1_*.js`: optional 1-minute bars
- `public/data/etf/`: SPY/QQQ/IWM bars for VWAP, generated by `scripts/fetch_etf_bars.py` (see below)
- `scripts/realdata.stats.test.ts`: how the divergence detector and swing stop behave on all trades (`STATS=1 npx vitest run realdata`)

## 1-minute chart

The replay can show 1-minute bars for timing exits. Export them on the machine with the raw Dukascopy files (the repo folder should sit next to `bear-backtest/` and the `bear-ideas_*.csv` files, or pass `--raw <folder>`): `python build_data.py --m1-only`. On Windows you may first need `pip install tzdata`. It writes `public/data/m1_<instrument>_<year>.js` (trade days, 8:30–16:00 ET) and `public/data/m1_index.js`. Commit and push those, and the **1 min** button appears for trades that have data.

RSI Trader's chart screenshots are never published with the site. Users load them from their device or a private GitHub repo, and they're cached in the browser.

## Updating the data

When new trades are added, run these in order, then commit and push `public/data/`:

```bash
python build_data.py                        # trades, messages, option paths, 5-minute bars
python build_data.py --m1-only              # 1-minute bars (needs the raw Dukascopy files, see above)
python scripts/fetch_etf_bars.py            # VWAP: 5-minute ETF bars for any new month
python scripts/fetch_etf_bars.py --m1       # VWAP: 1-minute ETF bars for any new trade day
```

Without the last two steps the new trades still work, but show no VWAP line.

`fetch_etf_bars.py` pulls regular-hours bars with full-market (SIP) volume from Alpaca's free market-data API, so VWAP matches TradingView's default (session from 09:30, hlc3 × volume). It only fetches what is missing; add `--force` to fetch everything again. It needs an Alpaca key ID and secret sent as the `APCA-API-KEY-ID` and `APCA-API-SECRET-KEY` headers to `data.alpaca.markets`:

- on your own machine, set `ALPACA_KEY_ID` and `ALPACA_SECRET` in the environment (a free paper-trading account's keys are enough);
- in a Claude Code cloud session, they can be saved as network secrets on the environment instead, and the proxy adds them.

The free plan has no data from the last 15 minutes and allows about 200 requests a minute; a full refetch of every month and trade day takes about 15 minutes.
